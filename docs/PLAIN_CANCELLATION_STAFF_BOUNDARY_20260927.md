# 予約だけの取消入口をスタッフ処理へ限定

QW-20260917-001。ローカル実装、DB420未適用・本番未反映。

`cancel-with-lock` のUI呼出元は店舗の予約一覧と公演中止処理だけだが、顧客もAPI・DBを直接呼べた。貸切グループや取消通知を同期しない予約だけの取消が可能だったため、APIは取得前にスタッフ認証を要求し、DBも同組織の管理者または有効スタッフを要求する。

実DBには3引数と2引数の署名が残っていた。両方を修正し、2引数は3引数へ委譲する。通常の顧客取消は既存のグループ・通知付き入口を維持。実行ACLとRLSは変更しない。匿名・本人顧客・無効スタッフ・別組織スタッフ/管理者を拒否する。

予約変更前に公演行をNOWAITでロックし、競合時は変更しない。中止フラグNULLの旧公演も通常人数を再集計し、来場済みを含める。中止済み公演の人数は保持する。補償付き中止は事前に公演と予約をロックしてスタッフ本人として呼ぶ既存経路を維持する。

隔離DBで実420 DDLの両署名、拒否時無変更、通常顧客の通知付き取消、管理者/有効スタッフ、NULL/来場済み/中止公演、所有者経由で事前ロック済みのスタッフ呼出し、人数更新失敗時の予約rollback、復元再適用が成功。補償全体（クーポン・通知生成）の実行はこのテストに含まない。NOWAITの複数接続同時競合はPGliteでは未再現。API関連34件、全体verify（型検査・lint・build）成功。独立レビューP1/P2なし。

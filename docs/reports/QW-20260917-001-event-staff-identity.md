# 公演担当のID保持（QW-20260917-001）

スタッフ改名後に `gms` だけが変わり、`gm_roles` が旧名に残るため、受付等が通常GMとして扱われる経路があった。公演担当のスタッフID・役割・表示順を `schedule_event_staff_assignments` に保持し、給与はこの関係を読む。

旧クライアント、貸切確定RPC、コピー、インポートの名前入力は、公演の書込みトリガーで同じトランザクション中に変換する。一般的な逆方向トリガーは置かない。スタッフ改名だけは専用トリガーで既存の名前配列と役割キーを同時更新する。既存の expected_updated_at 条件はそのまま維持する。

- 一意に照合できた担当だけstaff_idを設定。未登録名と重複名は元の順序・名前・役割を残す。
- 新規の未登録名、重複、別組織スタッフ、不正な役割、改名後の古い役割キーを拒否。既存の未照合履歴は編集可能だが、後から同名スタッフが増えても勝手に結び付けない。
- 担当履歴のあるスタッフ削除を制約で防止し、非アクティブ化を案内。公演削除は従来どおり関連担当行も削除する。
- 新関係はブラウザから直接読めず、認証済み組織で絞ったサーバーAPIのみが取得する。
- 未確認担当者を給与画面に表示。未解決公演または担当者がある月の合計を参考値と明記する。報酬制度や既存の日付別履歴選択は変更しない。

検証環境: 14,627担当枠を保持（解決12,070、未登録2,541、重複16枠）。実データの改名をロールバック付きで検証し、全ID・役割の不変と旧表示の追従を確認。unit 441件、verify（型・lint・build・安全チェック）、DB回帰（改名、古いキー、他組織、失敗時取り消し、0名、削除、復旧）を通過。

本番残件: 作品不明の2026年9月1日・11日・15日・24日・25日は、作品と給与対象の事実確認待ち。過去の未登録担当も別人へ推測で割り当てない。予約のassigned_staff/gm_staffは既存の名前互換を継続し、旧配列の廃止や全入力のID専用化は未実施。正規化を追加しただけで構造改善全体完了とはしない。

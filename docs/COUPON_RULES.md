# クーポンの条件と適用順序

案件 QW-20260926-005。

## 管理の単位

- キャンペーンは組織に所属する。割引額、配布期間、利用期間、最低金額、曜日・時間帯、併用、同作品の再利用、対象店舗・作品を管理する。
- 店舗未選択は組織内の全店舗。作品指定はその組織が導入している作品から選ぶ。旧作品マスタID指定も読取互換を維持する。
- 「クーポンの利用を受け付ける」は組織共通 → 店舗 → シナリオ → 公演の順に上書きする。適用元の表示と共通設定に戻す操作は既存の設定継承UIを使う。予約成立時に条件を保存し、予約済み分は遡及変更しない。貸切の公演未確定申込も、判明している店舗・作品までで解決する。
- 割引額や配布済みの利用条件はキャンペーン・保有クーポンの条件であり、公演の設定から変更しない。

## 配布と利用の区別

配布停止・配布期間終了は、新規配布を止める設定。配布済み分は利用期間・保有分の期限・残回数・取消状態で判定する。取消は既存の顧客クーポン取消操作を使う。

利用条件は配布時に `customer_coupons.rules_snapshot` に保存する。既存分は過去の配布時点を復元できないため移行直前のキャンペーン条件を保持する。過去の使用履歴・期限・残回数は書き換えない。編集後の条件は新たに配布する分に適用する。

## 利用経路

予約RPCとマイページの使用記録は、同じ `coupon_discount_for_event` と使用履歴INSERT時のトリガーで検証する。予約画面の既存のクーポン選択停止状態は変更していない。予約RPCのクーポン引数は既存API互換として保護する。

- 本人の保有分、同じ組織の有効な予約、公演取消・残回数・期限・対象・最低金額・曜日・時間帯を確認する。
- 貸切は参加済みメンバーも対象。併用可否は同じ予約全体で検査する。同作品の再利用は顧客単位で検査し、同一予約内は併用設定に従う。
- 割合割引は予約の `total_price` に対して計算し、円単位で四捨五入する。予約に記録された割引の合計は予約金額を超えない。
- マイページは確定前にDBで利用可否と割引額を確認する。確定時にも再検証する。使用記録であり、会計済み金額や決済の返金・徴収を変更する操作ではない。
- 利用時は顧客・クーポン・予約の行をロックし、予約をロックしてから最新の金額・状態を読む。使用履歴のトリガーだけが回数を1減らす。予約RPCからの重複減算は廃止する。
- 同じ保有クーポンと予約への再試行は既存結果を返し、2回消費しない。使用取消も同じ履歴の再試行で回数を重複復元せず、取消済みクーポンを有効に戻さない。
- 予約なしの利用記録へのフォールバックは行わない。直接顧客からservice専用RPCを呼べない。

## 期限内・予約ありでも使えない場合の追加対応

配布期間は取得時だけ判定し、配布済みは保持した使用期限と条件で判定する。
予約候補は本日（JST）以降の確定・チェックイン済み予約を表示し、当日の開始3時間前という表示制限を除去した。候補には公演日も表示する。予約取得失敗を「予約なし」に置き換えず、エラーと再読み込みを表示する。
利用時の所有者・組織・対象作品/店舗・割引・残回数の検証は共通RPCに残す。過去日や未確定の予約を候補に出さない。追加のAPI回帰で未来予約・JST日付境界・配布終了後の使用期限内クーポン・取得失敗を検証する。

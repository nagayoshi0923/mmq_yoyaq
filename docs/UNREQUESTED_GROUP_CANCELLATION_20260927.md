# 申込前グループの取消

案件QW-20260917-001。グループ取消ボタンは申込前に表示されていたが、保存は汎用の直接UPDATEで予約申込との競合を確認していなかった。

専用RPCがグループをロックし、主催者本人・申込前状態・有効予約なしを検証する。group.reservation_idだけでなく予約からの逆参照も確認する。取消済み予約の履歴は残せるが、異組織・別グループ・欠損リンクは拒否する。承認・取消のreservation-firstロックとはNOWAITで待ち合いを避ける。既に取消済みで有効予約もない場合は安全に成功を返す。

2画面とフックを専用RPCに移行し、申込済み予約をこの操作では取り消せないことを明示する。失敗理由を画面へ返し、false応答を成功扱いしない。予約済みの取消導線・期限判定・料金処理は別途整備を続ける。

# 公演スケジュールの自動化（QW-20261113-001）

2026-11-13 社長決定。予約公開を早めるため、「シフトを集めてから組む」をやめて
**「作品を先に決める → 回せる GM に出勤を募集する → GM が決まったら公開」** の順に変える。まず大久保店から始める。

## なぜ（本番データ 2026-11-13 時点、読み取りのみ）

- シフト提出は前月 4〜10 日にほぼ全員そろうが、オープン公演の登録は前月の中旬〜下旬（11 月分は 10/17〜19）。
- 12 月分はシフトが 11/10 にそろっても、11/13 時点でオープン公演は 18 件ほど。
- 遅れの原因: ①シフトが 1 か月前にしか集まらない ②そろってから手で組むのに 1〜2 週間かかる（出勤できる人×回せる作品×他との兼ね合いのチェックが多い）。

## 決めたこと

| 項目 | 決定 |
|---|---|
| 作品の選び方 | 予約傾向・新作・店舗ごとの回せる作品の縛り・同じ作品が続かない。GM の出勤可能日は作品選びでは見ない |
| 固定枠 | 店舗ごとに曜日×時間帯で細かく決める |
| GM 募集 | 回せる GM 全員に Discord で一斉に送り、最初に「担当できます」を押した 1 人で確定 |
| 返事がないとき | 2 日待って返事がなければ演目を変える |
| 公開 | GM が決まったら管理者の確認なしで即公開 |
| GM 決定前の公開 | しない（先行公開案は取り下げ） |
| シフト提出 | 当面残す。募集が回り始めたら廃止を検討 |

画面の土台: Figma 壁打ち「オープン公演｜GM募集フロー案｜2026-11-02」（goL6q69LSpsbwjlS8K27FC, node 965:415）。
Figma 時点の「回答だけでは確定しない」は、上の決定（先着 1 人で確定・即公開）で置き換える。

## 段階

1. **固定枠と下書き自動作成**（このPR）
   - `schedule_slot_rules`（店舗×曜日×時間帯、7=祝日）。閲覧はスタッフ、保存は管理者（admin）のみ。
   - スケジュール管理の「公演の下書きを自動で作る」（管理者のみ）: 固定枠の空いている枠に作品を当てた案を出し、選んだ案を
     **オープン公演・GM 未定・予約受付 OFF** で登録する（手で作る公演と同じ「最初は非公開」）。
   - 作品の条件（外せない）: メイン GM がいる／その店舗で公演できる（available_stores）／公演期間内／同じ日のキット数を超えない／同じ店舗で 7 日以内に同じ作品がない。
   - 点数: 予約の入りやすさ（直近 120 日のオープン公演の埋まり具合 6 割＋貸切件数 4 割）＋新作 0.5 − その月に入れた回数 × 0.3。
   - 純粋関数 `src/pages/ScheduleManager/utils/autoDraft.ts`、読み書きは `/api/schedule?type=auto-draft-data|auto-draft-rules`。
2. **GM 一斉募集 → 先着確定 → 即公開**: 下書きをまとめて OK → 回せる GM（同じ時間に他の公演がない人）へ Discord で募集（既存の貸切 GM 確認と同じ個別チャンネル・ボタン）→ 最初の「担当できます」で GM を入れて予約受付 ON。公演セルに募集状況を表示。1 公演ずつの「シフト募集モード」も残す。
3. **2 日で演目を入れ替えて再募集**、GM テスト候補（予約は入るのに回せる GM が少ない作品）の一覧。

## 外部送信

段階 1 は外部へ何も送らない（schedule_events に HTTP を呼ぶトリガーは無い、2026-11-13 staging で確認）。
段階 2 以降の Discord 送信は Edge Function 先頭の `outbound-guard` で検証環境から実在の宛先へ送らない。

# 顧客取消の期限・料金判定をDB経路へ適用

QW-20260917-001。DB430はローカル実装、本番未反映。

APIのセルフ取消判定を通さず、通知付きRPCを直接呼ぶと本人の予約を期限後や料金発生期間にも取り消せた。内部の顧客取消ガードをグループ/公演のロック取得後・状態変更前へ追加し、通知付き入口にも同じ拒否を適用する。スタッフの同組織権限は維持する。

完全な予約スナップショットはその期限・料金条件のみを使用。不完全・不正な保存規定と公演不整合はP0053、期限後または料金発生期間はP0052で拒否する。APIは具体的な案内へ変換し、拒否後に料金台帳を作らない。旧予約の期限は共通実効設定、料金は既存の互換判定を維持し、過去の請求規定を確定する変更ではない。0は既存の無料セルフ期間（通常48時間・貸切720時間）へ読み替える。

隔離DBの実DDLで、保存規定維持・旧予約・期限と料金・不完全規定・公演組織・本人/スタッフ・匿名・内部関数直接実行拒否・通知・復元再適用を検証。締切ちょうど/直前直後、料金発生ちょうど、同じ料金閾値の配列順も確認。共通実効設定の呼び出しはスタブを使い、設定階層本体の再実装はしていない。複数セッションのロック競合は未再現。API関連37件も成功。独立レビューでcategoryだけが貸切を示す旧公演の判定漏れを修正し、SQLのキー判定とAPIの公演SELECTにcategoryを追加、双方の回帰テストを追加した。最終verify（型検査・lint・build）成功、独立再レビューでP1/P2なし。

実予約の取消、クーポン発行、返金、通知送信は検証で行わない。取消料金台帳の一括保存、未確定貸切のセルフ取消、全領域残件は継続する。

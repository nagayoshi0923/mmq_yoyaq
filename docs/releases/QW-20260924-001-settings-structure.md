# QW-20260924-001 設定の対象と適用範囲を整理

## 合意した範囲

2026-09-24、利用者は「組織共通・店舗別・作品別・公演別」の整理案と、MMQ全体管理の分離、共通作品情報/自社変更の識別、設定の影響範囲・優先順位の明示、関連画面からの導線、過去・予約済みへの適用説明を確認し、実装を指示した。

本番反映の指示とは区別する。既存の設定値を移行・一括変更せず、DB migrationは不要。公演モーダル・公演カードの見た目は維持する。

## 実装

- 設定一覧とサイドバーを同じ設定カタログで分類。MMQ全体管理は既存の権限判定を使用。
- 21の既存タブを保持し、混在していた時間帯・通知を分離する2タブを追加。料金/売上レポートの既存画面は削除せず、適用確認が必要な点を明示。
- 組織共通の時間帯は `organization-time-slots`、店舗所要時間は従来の `performance-schedule`。組織通知は従来の `notifications`、店舗通知は `store-notifications`。保存は表示対象のみ。
- 設定する店舗をURLの `store` に保持。所属店舗一覧で検証し、不明なIDを別店舗に置き換えない。店舗別フォームは店舗単位で作り直し、先頭店舗を勝手に読む動作を修正。全店舗一括選択は実際に対応するキャンセル設定のみ。営業時間の既存「全店舗に適用」は維持。
- 各設定ページに対象・適用範囲・関連設定を表示。店舗詳細から当該店舗の設定を開く。作品編集から組織共通の募集/報酬・店舗メールへ進める。未保存の編集を失わないようモーダルからは別タブと明示。
- 作品の共通情報/自社設定を11項目で比較。共通に戻すと実際に上書き列をnullへ戻す。未変更フィールドは元のnull/明示値を保持し、別項目の保存で共通参照を固定コピーに変えない。共通と同値の明示設定、0、空配列も区別。
- 共通作品の読取りAPIに注意テーマを追加（更新許可の追加なし）。設定元読取り失敗は保存を止め、作品の直接保存失敗を成功表示しない。保存完了後に関連一覧を再取得する。

## 適用の説明

設定全体に単一の継承順を新設しない。予約確定/貸切確定メールは公演→作品→店舗→標準、募集は共通参照/個別指定、給与は適用日の履歴という既存動作を説明する。料金・予約条件の既存スナップショットや送信済みメールは一括更新しない。受付締切・開催判断・キャンセル期限を区別する。

## 検証

- 全unitテスト、verify（型・lint・ビルド・既存安全検査）。既存lint警告57件。
- ローカルの隔離した画面fixtureで5件: 4分類/管理者表示、店舗Bだけへの保存と店舗A切替、組織/店舗通知の独立保存、組織時間帯の保存先、共通情報への復帰。
- PC/スマートフォンの表示と横はみ出しを確認。
- 実データへの書込み・通知のテスト送信・本番配備なし。

## 残る既存仕様

- 営業時間の特別営業/休業日には保存処理との不一致がある。今回の分類・導線変更と別の不具合で、DB列と適用先の整合が必要。
- 独立した料金設定・売上レポート設定の実運用連動は未確認。新しい自動課金・自動送信を実装したとは扱わない。
- 外部サービスの秘密情報を編集する新画面や権限拡大は追加していない。
- 公演/予約の既存値に対する適用方式自体は変更していない。

## 確認手順

1. 設定 → 設定一覧：4区分と範囲切替を確認。一般管理者にMMQ全体の案内が出ないこと。
2. 店舗管理 → 店舗編集 → 予約の受付：その店舗が選択されること。店舗切替で対象値が切り替わること。
3. 設定 → 組織共通 → 公演の時間帯/通知：店舗別の入力が混在しないこと。
4. 設定 → 店舗別 → 標準の公演時間/店舗の予約通知：選択中店舗の項目のみ表示すること。
5. シナリオ管理 → 作品編集 → 共通情報と自社設定：設定元と共通値、自社値を確認。検証データで「共通情報に戻す」→保存→再表示し、共通参照になること。
6. スケジュール管理 → 公演の設定と適用範囲：募集・受付・キャンセルの区別を確認。

本番反映はこの差分だけを確認して行い、stagingにある別案件の未反映変更を混ぜない。

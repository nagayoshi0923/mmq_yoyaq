判定は DB だけで行います。画面（作品ページの貸切申込・グループの候補日追加・マイページ）は DB の結果をそのまま出し、保存も同じ関数で確かめます。
作品ページから進む申込の確認画面（候補の追加・送信前の再検証）と、カレンダー・リストから開く申込ページの候補の時刻も、同じ `private_booking_candidate_slot_availability` の結果を使います。
確認画面は DB が返した開始・終了をそのまま表示・送信し、作品の所要時間から終了を計算し直さない（特別営業日 I5 などは DB だけが知っているため。2026-10-20 監査 R1）。表示する候補・選べない理由・送信前の再検証は同じ問い合わせの結果から作る。
グループから店舗に申し込む申込シート（`groupPage/booking/requestSheetModel.ts`・`bookingRequest.ts`・`submitBookingRequest.ts`）も、候補日の開始・終了は `private_group_candidate_dates` に DB が確定した値をそのまま表示・送信する。送る直前にグループを読み直し、出していた時刻と違えば「候補日の時刻が更新されました。確認してください」と出して送らない。

- 表示: `private_booking_candidate_slot_availability`（作品ページ）／`private_group_candidate_slot_availability`（グループ。参加者とスタッフだけ）
- 保存: `private_group_add_candidate_dates`（候補の追加）／`create_private_group_atomic`（グループ作成時の候補）／`create_private_booking_request`（店舗への申込。申込シート・申込確認画面の送信。送る店舗だけで）／`private_group_set_preferred_stores`（希望店舗の変更。新しい希望店舗で入らない候補は外す）。どれも候補 1 件ごとに `private_booking_assert_candidate` で確かめる
- 店舗ごとの判定（表示と保存が使う内部関数）: `private_booking_slot_store_fit`、開始時刻の選び方 `private_booking_pick_start`
- 店舗の一覧（画面）: 希望店舗の表示・選択は `isStorePlayableForScenario`（`src/lib/scenarioStoreHint.ts`）で I12 と同じ条件にそろえる（作品ページ・申込確認・日時から選ぶ作品選択・グループ作成画面）
- 作品（グループ作成）: `create_private_group_atomic` は公開中（`org_status='available'`）・貸切受付 ON（`accepts_private_booking`）・出張限定でない（`scenario_kind<>'offsite_only'`）作品だけを受け付け、それ以外は「この作品はいま貸切を受け付けていません」で弾く。グループ作成画面の作品の読み込みも同じ条件で絞る。既存のグループには影響しない

## 作品選択前の入口（公開カレンダー・リスト）

作品選択後の候補日時は引き続き上記のDB判定を使います。作品選択前の入口は本番 #1073・#1077と同じ公開受付情報で、店舗ごとの休業日・営業時間・有効枠・募集停止・公開／非公開の占有を判定します。取得中・取得失敗は申込枠を出しません。受付可能な店舗だけを次の作品選択画面へ渡します。

- 営業設定がある店舗は有効枠だけを使い、開店前・閉店後に開始しません。作品未選択の入口では朝・夜を補いません。設定がない店舗の入口は平日昼13:00・夜19:00、土日祝朝09:00・昼14:00・夜19:00を既定にします。
- リストの「すべて」は表示対象の全店舗を検査し、各行の店舗に受付可能な枠だけを表示します。カレンダーは店舗選択後に選択店を検査します。
- 募集停止中の昼、休業日の全枠、平日の無効な朝、同時間帯の占有公演がある枠は申込を出しません。満席／体験済みを非表示にしても占有は残ります。複数店のうち1店だけ停止／占有の場合、受付可能店だけを次へ渡します。
- 例: 札幌店が平日朝を無効、昼13時／夜19時に設定している場合、朝は出さず昼／夜だけを出します。定休日は全枠を出しません。大久保店10/31昼が募集停止の場合、前の公演終了後に余白があっても昼の申込を出しません。

### 日時を選んだあとの作品選択（`/{org}/private-booking-select?date=&slot=&time=`）

- 作品一覧: その日に**日付だけで決まる理由**（手順 1 の `past_deadline`・`not_recruiting`・`outside_period`）で申し込めない作品は、カードに「この日は申し込めません（作品の公演期間外です）」のように理由を出し、押せない。判定は `private_booking_scenario_date_reasons`（保存と同じ `assert_private_booking_candidate_date` を作品ごとに通す）。作品数 × 店舗数の空き判定は一覧では行わない。
- 選んだ作品: 選んだ日付 × 時間帯を、希望店舗（未選択なら上演できる全店舗）で `private_booking_candidate_slot_availability` に通す。選べなければ理由（上の表の文面）を確認ボタンのすぐ上に出し、進めない。選べるときは DB が決めた開始時刻を出し（「この作品の開始時刻 18:30 で申し込みます」。押したチップの時刻と違えばそう書く）、その時刻で申込確認画面へ渡す。
- 希望店舗: 作品を上演できる店舗（`isStorePlayableForScenario`）だけを出す（臨時会場・上演店舗の指定外は「対応不可」で並べない）。

## 判定の手順

日付 × 枠（午前・午後・夜）ごとに、次の順で決めます。

1. **日付で落とす**: 受付締切（I14）より前 → `past_deadline`、申し込める範囲（I21。今日 + 日数）より先 → `too_far`、作品の貸切募集期間外（I13）→ `not_recruiting`、作品の公演期間外（I13）→ `outside_period`。
2. **店舗で落とす**: 希望店舗のうち作品の公演可能店舗（I12）が 1 つも無い → `no_store_for_scenario`。
3. **作品の時間帯で落とす**: 作品の貸切時間枠（I10）にその枠が無い → `slot_not_allowed`。土日祝の扱いは店舗ごと（特別営業日 I5 の店舗だけ土日祝の枠になる）なので店舗ごとに決め、すべての店舗で無いときにこの理由になる。
4. **店舗ごとに隙間を探す**（公演可能な希望店舗それぞれで、他店の条件は混ぜない）。土日祝（土日・祝日 I7・独自休日 I8、その店舗の特別営業日 I5）は土日祝の所要時間と設定を使う。
   1. **営業時間**: その日の枠（I1〜I5 と作品の開始時刻 I11 を反映）から、「最初の枠の開始」〜「閉店（最大 23:00）」を営業中とする。休業日は全日占有。店舗の設定で無効な枠（I2）はその店舗では候補にしない（`closed`）。
   2. **占有区間**を作る:
      - 公演（I16）: `開始 − 公演側の準備時間` 〜 `終了 + この作品の準備時間`（I15。前後の日をまたぐ公演も含む）
      - 受付停止枠（I17）: その枠の時間帯全体（朝 = 朝の開始〜13:00、昼 = 昼の開始〜19:00、夜 = 夜の開始〜閉店）
      - 貸切募集停止期間（I6）: 全日
   3. **隙間** = 営業中 − 占有区間。
   4. **開始時刻の範囲**: 隙間ごとに `[隙間の開始, 隙間の終わり − 所要時間]`。さらにその枠に属する条件として「公演が枠の時間帯（標準開始〜枠の終わり）にかかり、枠の終わりより前に始まる」こと。特例（I18）は 19:30 より前に始めない（ただし 19:30 開始で 23:00 を超えるときは 23:00 終わりまで繰り上げてよい）。
   5. **開始時刻を選ぶ**: 標準開始（I3 を I11 で上書き、特例は 19:30）が範囲に入ればそれ。入らなければ範囲内で標準に最も近い時刻を 15 分刻みで選ぶ（前の公演の終わり＋準備時間なら切り上げ、次の公演に合わせて早めるなら切り捨て。丸めで範囲から外れるときは範囲の端の時刻）。終了 = 開始 + 所要時間。
      - **2026-10-15 社長決定: 作品の開始時刻設定（I11）は絶対。入らなければ選べない。** 作品にその枠（平日／土日祝ごと）の開始時刻があるときは、その時刻だけを試し、範囲に入らなければ近い時刻にずらさず選べない（理由 `start_fixed`「この作品の開始時刻 14:30 では前後の公演と重なります」）。設定が無い枠は上のとおりずらす。
   - これで「夜の標準 19:00 で閉店を超えるなら、前に公演が無ければ 23:00 終わりまで繰り上げる」「午後の公演が夜の時間帯にかかっても、夜に公演が無ければ受け付ける」が同じ規則で決まります。
5. **複数店舗**: 1 店でも入れば選べる。表示する時刻は、標準開始で入る店舗があればその時刻（複数なら早いほう）、無ければ最も早く始められる店舗の時刻。標準からずらした時刻は画面に「18:30〜23:30 に調整」のように出す。
6. **入らないときの理由**（店舗ごとに決め、`conflict` → `blocked` → `closed` → `slot_not_allowed` の順に 1 つ採る）:
   - 営業時間だけで入らない → `closed`
   - 受付停止を無視しても公演と重なって入らない → `conflict`。隙間はあるが短いときは「空き 2 時間・必要 5 時間」の補足を付ける（その枠の時間帯にかかる隙間の最大長）
   - それ以外（受付停止・募集停止があるために入らない）→ `blocked`
   - 作品の開始時刻が決まっている枠（4-5）で `conflict` になったときは `start_fixed` として出す（文面は「この作品の開始時刻 HH:MM では前後の公演と重なります」）
7. **保存**: 画面が返した開始・終了を、同じ関数で「その開始時刻が範囲に入るか」で確かめる。終了は開始 + その店舗の所要時間と一致し 23:00 以内であること。入らなければ理由付きで弾く。作品の開始時刻が決まっている枠で、その時刻以外（旧来の画面が送る 14:00 など）は「この作品の開始時刻は HH:MM です」で弾く。開始は入るが終了が所要時間と合わない（画面を開いた後に所要時間が変わった）ときは「公演時間が更新されているか、営業時間内に収まりません」で弾く。
   - 候補の追加（`private_group_add_candidate_dates`）とグループ作成（`create_private_group_atomic`）は同じ検査（`private_booking_assert_candidate`）を通す。画面で選んだあとに公演・受付停止・設定が変わっていれば、グループ作成でも保存しない（2026-10-15）。
   - 店舗への申込（`create_private_booking_request`）も、グループの候補日の開始・終了を、**送る店舗だけ**で同じ検査に通す。候補を追加した後に店舗の枠・休業日・作品の開始時刻などが変わったとき、申込シートで希望店舗の一部だけに送るときに、受け付けない枠を送らない（2026-10-20。例 R34・R35）。
   - 希望店舗の変更（`private_group_set_preferred_stores`）は、新しい希望店舗で同じ検査に通し、どの店舗でも入らない候補を外す（画面は「空き枠のない候補日 N 件を削除しました」）。日付だけで決まる理由（締切・範囲・募集期間・公演期間）は店舗を変えても変わらないので外さず、申込の送信で弾く（2026-10-20。例 R36）。

## 変更するときの決まり

- 判定の SQL（上の一覧）・画面・この文書は**同じ PR で**変える。`npm run check:private-booking-rules` が、一覧のファイルを変えたのにこの文書が変わっていない変更を止める。
- 特例（作品名・店舗・日付で動きを変えるもの）を足すときは、必ず「入力」の表と「例」の表に行を足し、`supabase/tests/private_booking_rules_examples.sql` に同じ番号の確認を足す。
- 「例」の表の行を変えたら、テストの同じ番号も変える（番号を使い回さない。消した番号は欠番にする）。
- DB を変えるときは migration と同名の rollback、`supabase/structure/expected-function-overrides.json`／`staging.json` を staging の実物で更新する。

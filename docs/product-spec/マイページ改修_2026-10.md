## 1. 「予約」タブ

### サブタブ

「一般公演」「貸切」「キャンセル済み」の 3 つ。

- **一般公演**には貸切を出さない。貸切とは次のどれかに当てはまる予約:
  - `reservations.reservation_source` が `web_private`
  - `reservations.private_group_id` がある
  - 公演（`schedule_events`）の `category` が `private`、または `is_private_booking` が真
- 貸切はすべて「貸切」サブタブへ。

### 貸切サブタブ: 1 貸切 = 1 カード

- グループ（`private_groups`）と申込・予約（`reservations`）を結合して 1 枚にする。
  結び方は `private_groups.reservation_id` = `reservations.id`、または `reservations.private_group_id` = `private_groups.id`。
- グループの無い旧い貸切予約は、予約だけで 1 枚にする。

### 節と並び順（上から）

1. **あなたの対応が必要** — 自分に行動があるもの（下のラベル 1〜3）
2. **店舗の返事待ち** — 申込済みで店舗の確定を待っているもの
3. **主催者の準備待ち** — メンバーとして参加していて、主催者が候補日の登録・申込を進めるのを待っているもの（該当があるときだけ出す。段階 1 で追加した節）
4. **確定した貸切** — 公演日が今日以降の確定。日付の近い順。2 件まで出して「あと ○ 件表示」で展開
5. **終了した貸切・取り下げた申込** — 折りたたみ（既定は閉じる）。終了＝公演日を過ぎた確定。取り下げ・キャンセル済みは「キャンセル済み」サブタブに出すので、ここには件数だけ

### カードのヘッダー（左のラベル＝次にやること）

状態名ではなく **次にやること** を出す。判定の優先順:

1. 「主催者の引き継ぎに同意する」（段階 3 で使う。段階 1 ではラベル定義のみ）
2. 「アンケートに回答する」（確定後・公演日が今日以降・自分に未回答の公演前アンケートがある）
3. 日程まわり（グループが `gathering` / `date_adjusting` のとき）
   - 「候補日を決める」: 主催者で、候補日が 0 件
   - 「日程に回答する」: メンバーで、自分が未回答の候補日がある
   - 「申込に進む」: 主催者で、候補日がある（全員回答済みを含む）・未申込
4. 「店舗の返事待ち」（グループ `booking_requested`、または予約が `pending` / `pending_gm` / `gm_confirmed` / `pending_store`）
5. 「○/○(曜) 開催」（確定・公演日が今日以降）
6. 「終了」（確定・公演日を過ぎた）

補足: メンバーで回答済み（または候補日 0 件）のときは「主催者の準備待ち」（節 3）。

ヘッダー右は「あなたが主催」／「○○さんが主催」。その右に「操作」ボタンの置き場所（中身は段階 2。段階 1 では出さない）。

色はデザイントークンに従う。要対応＝紫系（貸切の色）、返事待ち＝琥珀系、確定＝緑系、終了＝灰色系。

### カードの中

- サムネイル、作品名
- 5 段階の進み具合: 招待 → 候補日 → 回答 → 申込 → 確定。確定後は「確定 → アンケート → 当日」に切り替え
- 1 行の説明文（例「候補日 2 件で申込中。店舗が日程を確定すると連絡が届きます」）。旧表示の「申込内容: 〜」「候補日 N 件で申込中」はここに統合
- 主ボタン 1 つ（次にやること）＋副ボタン「グループを開く」
- カードのどこを押してもグループページ（`/group/invite/{invite_code}`）へ。グループの無い旧い貸切予約だけ予約詳細（`/mypage/reservation/{id}`）へ

## 2. キャンセル済みサブタブ

- 貸切の取り下げ・キャンセルは **候補日を日付として出さない**（候補 1 件目が確定日のように見えるため）。
  申込中に取り下げたものは「候補日 N 件で申込中だったもの」と出す。確定後にキャンセルされたものは公演日を出してよい。
- ラベルを分ける（`reservations.cancellation_reason` で判定）:
  - 「取り下げ」: `PRIVATE_REQUEST_WITHDRAWN_REASON`（お客様による貸切申込の取り下げ）
  - 「店舗都合でキャンセル」: 店舗の却下（`貸切リクエストを却下しました`）、人数未達による公演中止（`人数未達による公演中止…`）
  - 「キャンセル」: お客様都合（`お客様によるキャンセル` など）と、判断できないものすべて

## 3. ヘッダー

お客様（`users.role = customer`）には名前の横の役割バッジ「顧客」を出さない。スタッフ・管理者・MMQ運営には従来どおり出す。

## 4. 数字の意味

| 場所 | 数字の意味 |
|---|---|
| 上段タブ「予約」のバッジ | **進行中の件数** = 一般公演の確定予約（公演日が今日以降）＋ 貸切の「要対応」「返事待ち」「主催者の準備待ち」「確定（未来）」の合計 |
| 上段タブ「クーポン」のバッジ | **使えるクーポンの枚数**（有効期限内・残り使用回数の合計） |
| 上段タブ「アルバム」のバッジ | **体験済み作品数**（アルバム一覧の件数） |
| サブタブ「一般公演」「貸切」「キャンセル済み」のバッジ | そのサブタブに出ている進行中の件数（キャンセル済みは件数） |
| プロフィール見出し | 「体験済み ○作品」（アルバムと同じ数え方。旧「○回参加」は廃止） |

## 5. 遊びたいリスト

作品ごとに「次の公演」1 件（日付・店舗・残席）を出し、押すと作品ページの公演選択（`?event={公演ID}`）へ。
公演が無ければ「予定なし・貸切リクエストできます」。公開ビュー `schedule_events_public` を 1 回の取得で全作品分読む（作品ごとに問い合わせない）。

## 9. 赤い操作と確認ダイアログ（影響を数字で見せる）

すべて `ConfirmDialog`。文言は `privateBookingConfirmText`（テストあり）。「メンバー」は自分以外の参加中の人数。

| 操作 | 処理 | 確認文の例 |
|---|---|---|
| グループを閉じる（申込前） | `cancel_unrequested_private_group_with_notice`（既存の `cancel_unrequested_private_group` で閉じ、チャットにお知らせを残す） | 「メンバー 3 名に知らせます。候補日 2 件と日程の回答は記録として残りますが、閉じたグループは元に戻せません。」 |
| 申込を取り下げる（返事待ち） | `/api/reservations?action=cancel-with-group-lock`（予約詳細の「取り下げる」と同じ。理由は `PRIVATE_REQUEST_WITHDRAWN_REASON`、店舗の承認画面に「お客様が取り下げ」） | 「店舗への申込を取り消し、グループも閉じます。メンバー 2 名に知らせます。…」 |
| キャンセル（確定後） | `reservationApi.cancel`（予約詳細の「キャンセル」と同じ。可否は予約詳細と同じキャンセル規定 `canCancelByPolicy`） | 「10/25(日)の貸切をキャンセルし、グループも閉じます。メンバー 1 名に知らせます。…」 |
| グループから抜ける（メンバー） | `private_group_leave`（既存） | 「…参加メンバーは 2 名から 1 名になります。」 |

### 「グループを閉じる」1 つにまとめた理由と内部処理

旧画面は「グループをキャンセル」（`cancel_unrequested_private_group`、状態を `cancelled` にするだけ）と「グループを削除する」（`delete_private_group`、候補日・回答・チャット・メンバーの行を消す。`gathering` のみ）の 2 本立てだった。

- 「グループを閉じる」は **`cancel_unrequested_private_group` 側（行を消さず履歴を残す）** を使う。理由: 日程調整中（`date_adjusting`。却下後の再調整を含む）でも使える／チャット・回答の記録が残り、問い合わせや店舗側の確認に使える／取り下げ・キャンセルと同じく「閉じた状態」で揃う。
- `delete_private_group` は画面から使わなくなった（RPC 自体は残す）。
- 閉じたグループの招待ページは「このグループは閉じられています」を出す。

### メンバーへの知らせ方（段階 2 時点）

- 「知らせる」＝グループのチャットに記録を残すこと（取り下げ・キャンセルの既存処理 `cancel_reservation_and_group_with_notice` と同じ方式）。閉じたグループの招待ページでも閉じたことが分かる。
- メール・プッシュでメンバーへ届ける仕組みは **段階 4（通知の整備）** で扱う。

## 10. メンバー管理シート

部品: `PrivateGroupMemberSheet.tsx`（マイページ・グループ画面で共通）。行は `toMemberRows`（主催者を先頭、あとは参加順）。

- 一覧: 名前・立場（主催者／会員＝アカウントあり／ゲスト）・日程回答の状況（回答済み／未回答／n/m 件回答／候補日なし）・参加日。
- 各行に「外す」（自分と主催者の行には出さない）。確認文「○○さんをグループから外しますか？ この方の日程回答は消えます。本人にはチャットで知らせます。」申込済み・確定後は「店舗に人数変更として伝わります。」を足す。
- ゲストの行に薄い字で「主催者になるにはアカウント登録が必要です」（段階 3 の布石）。
- 処理: `private_group_remove_member_with_notice`（既存の `private_group_remove_member` で外し、チャットに `member_removed`「○○さんがグループから外れました」を残す）。
- **店舗への人数変更の知らせ**: 既存の人数変更の通知経路は予約の人数変更（お客様へのメール）だけで、店舗向けは無かった。そこで既存の `discord_notification_queue` の `private_cancellation`（貸切キャンセル共有チャンネル `organization_settings.notification_settings.private_cancellation_channel_id`）に 1 行積む。申込済み・確定後で、取り消されていない申込があり、チャンネルが設定されているときだけ。本文は作品・予約番号・状態・参加人数（外す前 → 後、申込時）・外れた方。予約の `participant_count`（料金計算の元）は変えない。
- グループ画面の「メンバー招待・管理」シートの「退出させる」も同じ処理・同じ確認文（ボタン名は「外す」）に揃えた。

## 12. グループ画面

- 主催者の歯車＝8 の「操作」メニュー。メンバーの歯車は従来の設定シート（グループ情報・グループから抜ける・店舗に問い合わせる）。
- 右パネル（スマホは「日程・進捗」シートの先頭）に「申込内容」の箱（`BookingSummaryBox.tsx`）。
  - 申込前: 出さない（既存の「候補日程」と回答状況がその役）
  - 返事待ち: 状態・候補日（申込時の候補）・希望店舗・人数・予約番号・申込日時・「申込を取り下げる」（主催者のみ）
  - 確定後: 状態・日時・会場・人数・予約番号・「キャンセル」（主催者のみ。規定で不可なら無効にして理由を出す）
  - 人数は申込の `participant_count`（申込時の人数）。予約番号などはグループの読み取り RPC（`private_group_read_snapshot` の `linked_reservation`）から読む。招待リンクを開いただけの人（preview）には返さない。お客様情報・金額は含めない。
- マイページの予約詳細の「取り下げる」も残す（入口 2 つ、処理は 1 つ）。
- 右パネルの「グループをキャンセル」ボタンは「操作」メニューへ統合して外した。

  - リストは朝・昼・夜を列ではなく行に（2026-10-12 社長指示、見本 `ListRows.dc.html`）。日付の見出し（上に固定）→ その日の「朝 9:00〜12:00」「昼 14:00〜18:00」「夜 19:00〜23:00」の行（見出し＋罫線）→ 各行に公演を店舗名付きのカード（画像・時刻 ・ 店舗名・作品名 1 行省略・残席チップ）で縦に。店舗の並び順、同じ店舗内は時刻順。貸切で埋まった枠は行の末尾に灰色のチップ「高田馬場店 09:00 貸切」。公演も貸切も無い時間帯の行は出さない。会場の列は無くした。満席はカードを薄くして「満席・キャンセル待ち」。押すと作品ページを公演選択済みで開く（`?event=`）。PC はカード 2 列。空き枠（2026-10-12 社長要望）: 各時間帯の行の末尾、「貸切」チップの後ろに、公演も貸切も社内の予定も入っていない店舗を紫の枠のチップ「大塚店 空き ・ 貸切で申し込む ›」で出す（今日以降で、貸切申込の受付締切の日数より先の日だけ。臨時会場・オフィスは出さない）。空きが 3 店舗以上なら「空き N 店舗 ・ 貸切で申し込む ›」にまとめ、押すと店舗を選ぶ小さな一覧。全店舗が空きの時間帯も行を出す。押すと `/{組織}/private-booking-select?date=&store=&slot=&time=`（その日・時間帯・店舗を選んだ状態の貸切の作品選び）。空きの判定は元のリストの貸切申込ボタンと同じ目安（前の時間帯の終わりから 1 時間後が枠の終わりより前）で、作品ごとの正式な判定（`private_booking_candidate_slot_availability`、#1023）は作品を選んだ先の画面で行う（リストの時点では作品＝所要時間が決まらないため）。
  - カレンダーの今日より前の日は文言を出さず薄い地色だけ、過去だけの週は低くする。今日以降で公演の無い日（店舗を選んでいないとき）は、お客様向けの通常店舗すべてで受付可否を判定し、受付可の店舗がある時間帯だけ「HH:MM〜 貸切申込」を出す（押すと受付可の店舗をまとめて `/{組織}/private-booking-select` へ。2026-10-12 修正）。元は全マスに「店舗を選択して貸切申込」が出てスマホで画面の大半を占めていた。
- キービジュアル: 縦長・正方形は枠いっぱいに中央で切り抜き、横長は切り抜かずに全体を収めて余白は薄い地色（画像を読み込んだときの縦横比で切り替え）。枠はすべて 3:4（公演カード・残りわずか・作品から探す、全体トップも同じ）。作品の画像には位置・拡大率の設定が無い（`image_position`／`image_scale` はキャラクター画像だけ）ので、作品ページと同じ「全体を収める」に合わせた。

## MMQ 全体トップ `/`

並び: 見出しと横断検索 → 「{日付}に入れる公演」 → 残りわずか（全店舗） → 友だちと貸切で遊ぶ → 作品から探す（全国） → 参加店舗 → はじめての方へ → 店舗の方へ。

- 見出し「全国のマーダーミステリー公演を、ここから予約」、「参加店舗 N ・ 公演 M 件（今後 2 週間）」。
- 横断検索: エリア（店舗の住所の都道府県）・日付・人数。結果は全組織の公演を日付順、「組織名 店舗名」付き。押すとその組織の作品ページを公演・人数を選んだ状態で開く。
- 残りわずか: 店舗トップと同じ部品（組織名を付ける）。
- 作品から探す: 全国の公開作品（作品マスタ単位）。補足「N 店舗で上演・次回 M/D」。「すべての作品（全国 N）›」は既存の `/scenario`、作品は既存の全国版作品ページ `/scenario/{slug}`。
- 参加店舗: エリアのチップ（検索のエリアと共通）、組織カード（ロゴ／頭文字、店舗名 4 つ「ほか N 店舗」、作品数、「今週末 N 公演に空きあり」）→ 店舗トップ。
- 店舗の方へ: 既存の問い合わせフォーム `/contact?type=partnership`（種別「MMQ への参加（店舗の方）」を選んだ状態）。
- 公開情報だけを読む: `schedule_events_public`・`stores_public`・`organization_scenarios_with_master`＋公開キー RPC・稼働中の組織（名前・slug・ロゴ）。公演は 1000 件ずつ最大 5 回読む（今日から 8 週間）。

## 残席の言い方（社長決定 2026-10-12）

お客様向けの画面はすべてカレンダーと同じ「予約済み/定員」（例 2/8）＋「残少」（残席 1〜3）・「満席」にそろえる。共通の決まりは `src/lib/seatLabel.ts`（`seatCountText`・`isFewSeats`）。対象: 店舗トップの一覧カード・全体トップ（`seatState`。残りわずかの帯だけは本番の作品カードの「残N」チップ。成立間近の印はそのまま）、リスト、作品ページの公演一覧と申込パネル、予約確認、全国版の作品ページ、マイページの遊びたいリスト。キャンセル待ちの言い方と、エラーの文（「残り N 名分の空きしかありません」など）はそのまま。

## 数え方（1 つの計算元）

- 店舗数: `src/lib/publicStoreName.ts` の `countPublicStores`（臨時会場・休止中・オフィス〈名前に「オフィス」を含む店舗も〉を除く）。店舗トップの一言・全体トップの参加店舗数・組織カードで共通。
- 作品数: 店舗トップは予約サイトの作品一覧（公開キーで絞ったもの）＝`/{組織}/catalog` の件数。全体トップは稼働中の組織の公開作品を作品マスタで重複除き＝`/scenario` の件数（`/scenario` から休止中の組織の作品を外して揃えた）。
- 公演・残席・成立間近: `src/lib/publicPerformanceSearch.ts`。

## 店舗名（お客様向け）

`storeDisplayName`（`src/lib/publicStoreName.ts`）だけで決める。優先順:
1. 臨時会場は日付別の `temporary_venue_names`（無ければ `public_name`、それも無ければ「特設会場」）
2. 店舗設定の「お客様向けの名前」 `stores.public_name`（2026-10-11 追加。管理画面の店舗編集に入力欄）
3. 店舗名から組織名の接頭辞を外したもの（「クインズワルツ高田馬場店」→「高田馬場店」。外すと空なら元のまま）

使っている画面: 店舗トップ・全体トップ・フッターのアクセス・作品ページ（日程・会場アクセス・公演可能店舗・店舗の選択）・予約確認と予約確認メール（作品ページから渡る店舗名）・全国版作品ページ・貸切の作品選択／申込・グループページの作品情報の店舗一覧・マイページの予約カードと予約詳細。スタッフ向けの管理画面は従来どおり `name`／`short_name`。
DB 側も同じ決め方の関数 `public.customer_store_name(店舗, 日付, 予備の名前)` を使う（2026-10-11 追加）: グループページ・マイページの貸切カード（`get_private_group_schedules`・`private_group_performance_info`・`private_group_read_snapshot` の確定公演と希望店舗名・`private_group_handover_detail`）、前日のお知らせ（`customer_notice_on_reminder_sent`）、貸切確定のメール・お知らせ（`enqueue_private_approval_deliveries`・`approve_private_booking_with_notice`）、キャンセル待ちの案内（`capture_waitlist_notice_event`）、事前配役アンケートの催促（`claim_private_group_survey_reminders`）、中止とお詫び（`compensated_cancellation`）、キャンセルポリシーの公開ページ（`get_public_cancellation_policy_for_context`）。
Edge Function は `_shared/customer-store-name.ts`（前日メール・旧経路の貸切確定メール）を使い、キャンセル確認メールは店舗 ID から `customer_store_name` を引く。画面・メールで決め方が同じことは `src/lib/customerStoreName.parity.test.ts` で確かめる。
スタッフ向けの関数（公演チェック・募集・ライセンス報告など）と、貸切申込で保存する候補の店舗名（`create_private_booking_request`）は従来の `name`。本番反映は DB → Edge Function → 画面の順。

# キャンセル料・freee入金照合

案件 QW-20260908-001。実装・ローカル検証とステージングDBの先行適用まで。本番未反映、freee API未接続、自動実行未稼働。

通常キャンセルのメールが「24時間以内なら100%、それ以外0円」と計算していたため、受付時刻と予約時ポリシーを保存した料金台帳を参照するよう変更した。スタッフが操作しただけで主催者都合の無料キャンセルとは判定しない。

## MMQとAIの分担

- MMQ: キャンセル受付・席の解放、予約ポリシー、請求額、振込先、入金済み記録、通知の重複防止。
- freee: PayPay銀行と連携済みの入金明細。`wallet_txns` と口座の同期成功時刻をGETする。freee取引・仕訳・消込の更新や送金はしない。
- AI Manager: 予約時条件と運用事実をMMQから参照する。会社メールの対応内容・入金確認の根拠は会社用Google Driveのレポートに保存し、権限に応じた社内回答に利用する。会社メール返信の結果をMMQへ書き戻すことを完了条件にしない。今回のworkerを呼ぶ自動運用接続は未設定。

本番読取でQueen's Waltzの12設定すべてが `participant_total` と確認できた。直近キャンセルにはポリシーなしの旧予約も存在し、これらは0円にせず確認待ちにする。貸切の公演価格全額は別途確かな基準額が必要なため、今回の通常公演経路では確認待ち。

## 操作する画面

設定 → キャンセル設定 →「キャンセル料・振込先・freee入金確認を開く」。組織管理者のみ操作可能。

1. 正式な銀行・支店・口座番号・名義とfreee事業所/口座ID、運営通知先を登録する。旧口座は変更せず新バージョンを追加する。
2. キャンセル済み予約を選び、元連絡の受信時刻・受信記録・振込名義を確認する。不明時刻や不完全な予約ポリシーは保留。交通機関運休の確定には公式発表と来店への影響の記録が必要。
3. 案内本文を確認する。銀行振込、案内から7日、顧客の手数料負担。口座未設定では振込期限を開始しない。
4. freee照合プレビューで実際の摘要表記を確認する。金額・空白/全半角を正規化した名義・口座が一致し、双方1件だけを確定候補にする。名義の部分一致や推測変換はしない。
5. 条件確認後に照合を有効にする。実行は未払いの最古受付日から本日までの全口座明細を必要とし、明細IDの再利用、同名同額の複数候補、同期中、取得エラーを停止する。

振込先を変更した場合は未払い請求への変更通知を用意し、旧口座への入金も照合する。既に案内した振込期限はリセットしない。

## APIと有効化

- 管理者API: `GET /api/cancellation-billing`、`POST`の `action=settings|intake|reconcile|notices`。プレビューは `apply:false`。
- 自動実行入口: `POST /api/cancellation-billing?action=run`。専用Bearer認証で固定した1組織だけを処理する。既存の実行管理へ登録するまで定期実行されない。
- 公開ポリシー: `GET ?action=public-policy&organization=<slug>`。料金・振込・運休例外の文章だけを公開。口座・freee ID・請求情報は返さない。
- サーバーの秘密設定: `FREEE_ACCESS_TOKEN`、`CANCELLATION_BILLING_WORKER_SECRET`。環境との対応: `CANCELLATION_BILLING_ORGANIZATION_ID`。
- 実メール送信には組織側設定と `CANCELLATION_BILLING_SEND_ENABLED=true` の両方が必要。既存の組織メール設定の送信元・Resendキーを使用する。ステージングでは送信を有効にしない。

freee APIのOAuth認可と更新トークンの安全な保管・ローテーションは未接続。現段階の取得器はサーバーに渡されたアクセストークンを使い、失効時は停止する。銀行とfreeeの連携済みという事実だけでMMQからのAPI認証済みとは扱わない。

督促は期限超過かつ、全対象口座の最終同期成功から15分以内・期限後の同期・全期間の照合完了・曖昧候補なしの場合に1回のみ行い、運営もBCCへ含める。条件未達は保留。入金確認後は確認連絡を1回行う。取得日やfreee会計上の消込済み状態を銀行同期日時の代わりにしない。

送信結果不明・送信後の台帳更新失敗は通知を `unknown` として止める。自動再送せず、運営がメール配信結果と台帳を突合して復旧する。この復旧の専用画面は未実装。

## 受付経路による返信元（利用者訂正）

会社メールで受けたキャンセルは `contact.channel=company_email` と元メールID/スレッドIDを保持し、料金案内・督促・入金確認・口座変更をMMQ配信から除外する。通知APIは `companyReplies` として会社メール側へ渡す返信候補を返す。会社メールの返信・記録の運用接続は未完了であり、自動返信済みではない。返信結果の保存先は会社用Google Driveとし、MMQへの書き戻しを要求しない。

# 顧客キャンセル期限の設定階層整合

案件 QW-20260917-001。現時点はローカル実装・本番未反映。

予約時の取消規定が保存されていない旧予約だけ、APIの期限判定が店舗の reservation_settings を直接参照し、組織・作品・公演の上書きを無視していた。設定取得エラーも既定値へ置き換えていた。

顧客期限判定を api/_lib/customerCancellation.ts へ移し、旧予約はサービス権限の resolve_operating_setting に、サーバーで読んだ予約の組織IDと公演IDを渡す。公演から現在の店舗・作品を解決し、組織整合も検証する。公開サイト向けRPCの稼働店舗・公開状態制限は持ち込まない。数値0も有効値として取得するが、既存の無料セルフ取消期間（0は既定期間）の意味は変更しない。

完全な予約スナップショットは現在設定を取得せず使用。不完全なスナップショットは現在設定で補わない。旧予約の組織・公演不明、RPC失敗、期限の欠損・負値・非数値は503と具体的案内で拒否する。スタッフは従来どおり顧客期限判定の対象外。

新規18件と既存API12件が成功。組織/店舗/作品/公演の解決値、保存規定維持、0、貸切キー、欠損、取得エラー、スタッフ経路を対象とする。RPC階層本体は既存実装を再利用するため、このテストは実DB階層を再実装したものではない。全体verify成功（型検査・lint・build）、独立レビューP1/P2なし。本番DBのservice_role実行権と実公演コンテキストで数値を取得できることを読み取りトランザクションで確認した。

残件: 直接RPC経由の期限・料金判定、未確定貸切予約のセルフ取消、旧予約の料金規定、料金保存と通知の一括化、全領域棚卸し。実予約取消・返金は検証で実行しない。
